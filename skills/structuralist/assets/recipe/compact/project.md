# Fieldbook

Fieldbook helps field researchers return to their own observation notes.
Its current scope is reading a local collection of Markdown notes. It does not
schedule field visits or evaluate the scientific quality of an observation.

## Current browsing behavior

The default view lists visits with the most recent first. A reader can filter
that list by place without changing the underlying notes. Notes remain readable
as ordinary files.

This is the current owner of that behavior. The
[browsing summary](evolve/browsing-summary.md) explains the reasoning.
The remaining comparison question is in
[browsing evidence](evolve/browsing-evidence.md#remaining-question).

## Current working practice

For the present browsing-design work, use small walkthroughs to examine the
complete reading task and whether differing observations remain visible.
Navigation effort alone cannot establish a better reading experience. The
[worked observation](evidence/browsing-walkthrough.md) supports the local design
choice, not a claim about implemented behavior or measured user preference.

Choose methods and checks appropriate to the task. A filter defect can be
repaired against the accepted behavior; reconsidering field researchers' needs
can reopen the purpose and require other evidence. Revise this account when
the project's practice changes. No continuing steer or Event is required for
an ordinary repair.

## Documentation ownership

Keep purpose, accepted behavior, and working methods together in this account;
they are still small enough to review together. Use the existing evidence
account for the walkthrough's observations and limits, and Event discussions
for its alternatives and interpretation. Summaries explain the reasoning and
link accepted consequences here.

A behavior change updates this account and the affected realization and checks.
A new observation updates its evidence owner; revise this account when its
accepted conclusion or working method changes. Keep active worksheets temporary
and absorb useful results before removing them. Separate a responsibility only
when it needs independent maintenance. This local arrangement governs Fieldbook
when a general recipe suggests a different layout or method.
