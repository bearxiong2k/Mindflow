# Browsing evidence

A walkthrough with a small collection exposed the difference behind the
[browsing question](browsing-question.md): returning to yesterday's visit needed
one direct entry, while comparing visits benefited from narrowing to a place.
Place grouping was useful, but did not need to own the default view.

This supports a recent-visits default with a place filter. It is a bounded
observation, not evidence that every research workflow favors recency. The
accepted behavior is maintained in [the project account](../project.md).

## Remaining question

After selecting a place, should a reader compare visits in a combined view or
open separate notes? The walkthrough did not distinguish those options. Try a
comparison involving conflicting observations before committing to either.
For now, ordinary notes remain individually readable.
