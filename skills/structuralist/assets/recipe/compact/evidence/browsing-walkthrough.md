# Browsing walkthrough

This is fictional evidence for the Fieldbook worked example. It describes a
paper-layout comparison, not a shipped application, user study, or benchmark.

## Inputs and procedure

Use four note cards in this order of recency: Marsh yesterday (north path
blocked), Hill two days ago (clear view), Marsh three days ago (north path
passable), and Hill last week (poor visibility). Keep their dates and complete
text unchanged.

Lay out one recent-visits list with an optional place filter, and one list of
places whose entries reveal their visits. Walk the tasks below through both
layouts. Check which notes can be reached and what the reader must still
interpret. The early comparison counted navigation steps; the review also
examines whether the complete reading task can be performed.

## Observations and limits

| Task | Recent visits with a place filter | Place-first browsing |
| --- | --- | --- |
| Reopen the latest visit | The Marsh note is directly available | The reader first chooses Marsh |
| Find both Marsh visits | The filter leaves the two dated notes visible | Choosing Marsh reveals the same notes |
| Understand the differing path observations | Both notes must be read; the list alone supplies no interpretation | Both notes must be read; grouping supplies no interpretation |

Recency serves resumption while the filter retains a route to comparison.
Fewer navigation steps do not demonstrate better interpretation. This small
authored collection does not establish actual user preference, performance at
scale, or how an implemented reader behaves.
